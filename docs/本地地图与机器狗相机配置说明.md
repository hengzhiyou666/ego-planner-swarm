# 本地地图 + 机器狗双目相机与里程计配置说明

本文档说明：**不启动随机地图生成**，改为**加载本地地图**，并**订阅机器狗双目相机话题和里程计话题**时，需要修改与新增的参数、以及推荐用法。

---

## 一、整体思路

- **不启动**：`random_forest`（随机森林）、`mockamap`（Mock 地图）。
- **可选**：用“本地地图发布节点”加载 PCD 等静态地图，发布到 `/map_generator/global_cloud`（供可视化或后续融合；规划器栅格仍主要由实时传感器更新）。
- **规划器输入**：使用机器狗真实传感器与定位：
  - **里程计**：`odometry_topic`
  - **深度图**：`depth_topic`（双目深度或深度图话题）
  - **点云**：`cloud_topic`（双目/深度转的点云，与深度二选一或同时用）
  - **相机位姿**：`camera_pose_topic`（若用 `pose_type=1`；若用 `pose_type=2` 则用里程计代替）
- **不启动仿真**：不启动 `pcl_render_node`、`poscmd_2_odom`、`map_generator`、`mockamap`，仅启动规划相关节点（如 ego_planner）。

---

## 二、需要修改 / 传入的参数

### 2.1 话题类（必须与机器狗实际话题一致）

| 参数名 | 默认值（仿真） | 机器狗场景建议 | 说明 |
|--------|----------------|----------------|------|
| **odometry_topic** | `visual_slam/odom` | 机器狗里程计话题，如 `/odom` 或 `/robot_odom` | 规划器与 grid_map 的位姿来源 |
| **depth_topic** | `pcl_render_node/depth` | 双目深度图话题，如 `/camera/depth/image_rect_raw` 或 `/stereo/depth` | 用于 grid_map 深度投影（与点云二选一或同时用） |
| **cloud_topic** | `pcl_render_node/cloud` | 双目/深度点云话题，如 `/camera/depth/points` 或 `/stereo/points` | 用于 grid_map 点云更新 |
| **camera_pose_topic** | `pamera_pose` | 相机在世界/odom 下的位姿，如 `/camera_pose` 或由 TF 发布 | 仅当 **pose_type=1** 时必须；**pose_type=2** 时用里程计代替，可忽略 |

说明：

- 规划器内部通过 remap 使用：`grid_map/odom`、`grid_map/depth`、`grid_map/cloud`、`grid_map/pose`，对应上述四个话题。
- 机器狗若只有点云、没有深度图，可只配 `cloud_topic`，并保证 grid_map 能收到点云 + 里程计（见下文 pose_type）。

### 2.2 相机内参（必须与机器狗双目/深度相机一致）

| 参数名 | 默认值（示例） | 说明 |
|--------|----------------|------|
| **cx** | 321.04638671875 | 相机内参主点 x |
| **cy** | 243.44969177246094 | 相机内参主点 y |
| **fx** | 387.229248046875 | 焦距 x |
| **fy** | 387.229248046875 | 焦距 y |

这些会传给 `grid_map` 做深度图反投影，**必须与深度图/相机标定一致**（单位：像素，深度图单位需与 `k_depth_scaling_factor` 一致，见下）。

### 2.3 深度与栅格相关（按需调整）

| 参数名 | 默认值 | 说明 |
|--------|--------|------|
| **grid_map/k_depth_scaling_factor** | 1000.0 | 深度图数值到米的缩放（如 16 位毫米则为 1000） |
| **grid_map/depth_filter_mindist** | 0.2 | 深度最小有效距离 (m) |
| **grid_map/depth_filter_maxdist** | 5.0 | 深度最大有效距离 (m) |
| **grid_map/use_depth_filter** | true | 是否做深度过滤 |
| **grid_map/pose_type** | 1 | **1**：用 `grid_map/pose`（相机位姿）；**2**：用 `grid_map/odom` 作为相机位姿（适合相机固连机体） |

机器狗相机固连机体时，推荐 **pose_type=2**，只提供里程计 + 深度/点云即可，无需单独 `camera_pose_topic`。

### 2.4 地图范围（与本地地图/场景一致）

| 参数名 | 说明 |
|--------|------|
| **map_size_x_** / **map_size_y_** / **map_size_z_** | 规划栅格范围 (m)，应覆盖本地地图与可行走区域 |

### 2.5 本地地图（可选）

若需“加载本地地图”并发布到与仿真一致的接口：

- **发布话题**：`/map_generator/global_cloud`（类型：`sensor_msgs/PointCloud2`）。
- 可用本仓库提供的 **map_loader** 节点从 PCD 加载并发布，或自行写节点发布该话题。
- 规划器栅格主要由 **depth/cloud + odom** 实时更新；本地地图多用于可视化或后续扩展融合。

---

## 三、需要“不启动”的节点

- **random_forest**（随机地图）
- **mockamap_node**（Mock 地图）
- **pcl_render_node**（仿真深度/点云）
- **poscmd_2_odom** / **so3 仿真与控制**（真实机器狗不需要仿真控制）

即：使用“真实机器狗 + 本地地图”时，应使用**仅含规划与可选地图加载**的 launch，不包含上述节点。

---

## 四、推荐 launch 用法（真实机器狗 + 本地地图）

使用仓库提供的 **`robot.launch.py`**，传入机器狗话题与相机参数。

### 4.1 仅指定机器狗话题与相机内参（不加载 PCD）

```bash
ros2 launch ego_planner robot.launch.py \
  use_real_robot:=True \
  odometry_topic:=/odom \
  depth_topic:=/camera/depth/image_rect_raw \
  cloud_topic:=/camera/depth/points \
  camera_pose_topic:=/camera_pose \
  cx:=320.0 cy:=240.0 fx:=400.0 fy:=400.0
```

若相机固连机体、用里程计当相机位姿（推荐，无需单独相机位姿话题）：

```bash
ros2 launch ego_planner robot.launch.py \
  use_real_robot:=True \
  odometry_topic:=/odom \
  depth_topic:=/camera/depth/image_rect_raw \
  cloud_topic:=/camera/depth/points \
  pose_type:=2 \
  cx:=320.0 cy:=240.0 fx:=400.0 fy:=400.0
```

（此时可不设 `camera_pose_topic`。）

### 4.2 同时使用本地地图（PCD）

本地地图需由其他节点发布到 `/map_generator/global_cloud`（如自写节点或 pcl_ros 的 pcd_to_pointcloud）。规划器栅格仍主要由实时深度/点云更新。

```bash
# 先启动发布 /map_generator/global_cloud 的节点，再启动规划：
ros2 launch ego_planner robot.launch.py \
  use_real_robot:=True \
  odometry_topic:=/odom \
  depth_topic:=/camera/depth/image_rect_raw \
  cloud_topic:=/camera/depth/points \
  pose_type:=2 \
  cx:=320.0 cy:=240.0 fx:=400.0 fy:=400.0
```

## 五、参数速查表（机器狗 + 本地地图）

| 类别 | 参数 | 用途 |
|------|------|------|
| 开关 | use_real_robot | 关闭随机地图与仿真，使用真实话题 |
| 开关 | load_local_map | 是否启动本地地图发布（如 PCD→global_cloud） |
| 地图 | map_file | 本地地图路径（如 .pcd） |
| 话题 | odometry_topic | 机器狗里程计话题 |
| 话题 | depth_topic | 双目/深度图话题 |
| 话题 | cloud_topic | 点云话题 |
| 话题 | camera_pose_topic | 相机位姿（pose_type=1 时必填） |
| 相机 | cx, cy, fx, fy | 相机内参 |
| 栅格 | grid_map/pose_type | 1=相机位姿话题，2=用里程计当相机位姿 |
| 栅格 | grid_map/k_depth_scaling_factor | 深度图缩放（与深度单位一致） |
| 范围 | map_size_x_, map_size_y_, map_size_z_ | 规划地图范围 (m) |

---

## 六、机器狗侧需要发布的话题与要求

- **里程计**：`nav_msgs/Odometry`，坐标系与地图一致（如 odom 或 world）。
- **深度图**（若用深度）：`sensor_msgs/Image`，单位与 `k_depth_scaling_factor` 一致（如毫米则 1000）。
- **点云**（若用点云）：`sensor_msgs/PointCloud2`，建议为相机坐标系或已转换到 body/odom，并与 `grid_map/odom` 或 `grid_map/pose` 时间/坐标系一致。
- **相机位姿**（仅 pose_type=1）：`geometry_msgs/PoseStamped`，世界/odom 下相机位姿。

规划器用的是膨胀后的占据栅格（如 occupancy_buffer_inflate_）做碰撞检测；深度图负责「障碍 + 自由空间」的精细建图，点云负责「障碍 + 膨胀」的补充或替代（例如没有深度图时也可仅靠点云标障碍）

按上述参数在 launch 中配置好对应话题名与内参后，规划器即可在不启动随机地图与仿真的前提下，仅依赖本地地图（可选）和机器狗双目相机 + 里程计进行规划。
